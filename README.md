# 字幕对齐合并工具（Subtitle Align & Merge）

双版本 SRT 字幕对齐与合并的纯前端 Web 应用（React + TypeScript + Vite）。导入两份 SRT 后，系统按**时间重叠 + 文本相似度**进行顺序对齐，自动识别**一对一、一对多、多对一**以及单边片段；界面并排展示候选组与置信度，可逐组选择保留哪一版文本与时间轴，**未处理的冲突禁止导出**；冲突解决后还可对合并结果做**智能断行**（按 Unicode 字素簇计宽、动态规划选点、逐条预览、批量应用 / 恢复）。合并结果重新编号并校验时间单调性后下载为标准 SRT。无需任何外部服务，全部计算在本地完成。

## 一键启动（Docker）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8080**（宿主机端口 `8080` → 容器内 nginx `80`）。

> 旧版 Compose 可使用 `docker-compose up --build`。若 8080 端口被占用，修改 `docker-compose.yml` 中 `ports` 左侧端口即可。停止：`docker compose down`。

## 使用流程

1. **导入双版本**：为版本 A / B 分别选择、拖入或粘贴 SRT 内容（可点击「加载示例数据」快速体验）。
2. **顺序对齐**：点击「开始顺序对齐」，系统生成对齐组，每组标注类型（一对一 / 一对多 / 多对一 / 仅 A / 仅 B）与综合置信度（文本相似度 60% + 时间重叠 40%）。
3. **解决冲突**：文本不一致或一对多 / 多对一的组会被标记为冲突（红色边框）。逐组选择保留的文本（A / B / 自定义）与时间轴（A / B / 并集 / 自定义），或用工具栏批量操作（全用 A/B、用较长文本、按建议解决全部）；单边片段可选择保留或丢弃。
4. **智能断行**（可选）：切换到主区上方的「智能断行」页签：
   - 设置**每行最大显示宽度**与**最多行数**，可勾选**锁定已有手工换行**（锁定时每个原物理行不可跨越；解锁时原换行降级为空白、允许跨行合并）。
   - 宽度按 **Unicode 字素簇**计算：全角（CJK、全角标点、emoji 等）计 2，半角计 1；HTML（`<i>` 等）与 ASS（`{\an8}` 等）标签原样保留但不计宽。
   - 系统在**空白或标点边界**用动态规划选点，依次最小化：① 超限宽度总量、② 行宽差（各行距满宽缺口平方和）、③ 行首为`，。！？；：、）】》…`或行尾为`（【《…`的禁则惩罚、④ 行数。
   - 逐条并排预览**原文 → 断行结果**（右侧标注每行实际宽度，超限行标红、超行数行标黄）。满足限制的条目可单条「应用」或「批量应用」；已应用条目可单条「恢复」或「全部恢复」。**无法满足限制的条目会标明原因（存在不可断的超宽片段 / 最少行数超限）且不会被应用**。
   - 若应用断行后又改动了该条的文本选择或自定义文本，断行结果自动标记为「源已变更·待重应用」并暂停使用，重新应用或恢复即可。
5. **校验导出**：右侧实时预览合并结果（含已应用的断行）。存在未解决冲突或时间校验错误（开始时间倒退、区间重叠、时长非正、自定义时间非法）时无法导出；可勾选「自动修复时间重叠 / 非单调问题」。全部通过后点击「下载合并 SRT」，序号从 1 重新编排。

## 对齐算法说明

- 文本归一化：去除 HTML/ASS 标签、标点与空白后小写化，对中英文均适用；相似度采用 bigram Dice 系数。
- 时间重叠：两时间段交集的 Dice 系数。
- 顺序对齐：带合并移动的动态规划（类序列比对），每个位置允许 1:1 匹配、N:1 合并、1:N 合并（单侧最多连续 4 条）与跳过（产生单边片段），全局最大化累计得分；大文件自动切换带状 DP 控制计算量。

## 智能断行算法说明

- **字素簇切分**：优先使用 `Intl.Segmenter`（grapheme 粒度），旧环境回退到内置的组合记号 / ZWJ / 区域指示符合并逻辑；emoji 组合（如 👨‍👩‍👧）整体作为一个字素。
- **宽度计量**：二分查找全角码位表（CJK、假名、韩文、全角 ASCII、常见 emoji / 几何符号等），全角计 2、其余计 1；零宽字符（ZWJ、变体选择符等）计 0；HTML / ASS 标签整体宽度为 0 但原样保留；行首尾空白不计宽。
- **断点候选**：只在空白边界、标点之后（`\p{P}`）或开括号之前断开，词 / 字内部不断裂。
- **动态规划**：段内对「行起点 × 行终点 × 行数」做 DP，代价按字典序比较——超限宽度总量 → 行宽差（距满宽缺口平方和；同一行数下等价于最小化行宽方差，跨行数比较时优先填满、避免无谓多拆行）→ 行首 / 行尾禁则次数 → 行数；多个手工分段之间再用一次背包式 DP 分配行数，得到全局最优。
- **可行性判定**：贪心（每行尽量多装）求最少行数；最大不可断片段超过宽度上限时报「不可断超宽」（给出片段宽度与超出量），最少行数超过上限时报「行数超限」，此类条目**不应用**。异常超长条目（边界数超阈值）自动退化为贪心排法保证流畅。
- 结果带缓存（键为 宽度 / 行数 / 锁定开关 / 原文），调整设置时的逐条试算开销很低。

## 项目结构

```
├── src/
│   ├── lib/
│   │   ├── srt.ts          # SRT 解析 / 序列化 / 时间码
│   │   ├── similarity.ts   # 文本与时间相似度
│   │   ├── align.ts        # 顺序对齐动态规划（1:1 / 1:N / N:1 / 单边）
│   │   ├── merge.ts        # 合并决策、断行应用/失效、时间单调性校验、自动修复
│   │   ├── linebreak.ts    # 智能断行：字素簇计宽 + 动态规划选点
│   │   └── samples.ts      # 内置示例
│   ├── components/         # 导入、统计、工具栏、对齐组卡片、断行面板、导出面板
│   └── App.tsx             # 状态编排
├── Dockerfile              # 多阶段构建：node 构建 → nginx 托管
├── docker-compose.yml      # 一键启动，端口 8080 → 80
└── nginx.conf              # SPA 回退与静态资源缓存
```
